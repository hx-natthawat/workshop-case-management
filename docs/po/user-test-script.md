# สคริปต์ทดสอบกับผู้ใช้ · MVP ระบบแจ้งเคสผ่าน LINE

ใช้คู่กับแอปที่รันตาม `web/README.md` · ข้อมูลทั้งหมดในระบบเป็นข้อมูลสมมติ ห้ามใช้ข้อมูลส่วนบุคคลจริงระหว่างทดสอบ

## เตรียมก่อนเริ่ม

| รายการ | รายละเอียด |
| --- | --- |
| ผู้แจ้ง | ตั้งค่า `SIMULATOR_ACCESS_CODE` ใน `.env.local` แล้วแจ้งรหัสแก่ผู้ทดสอบ จากนั้นเปิด `/simulator` ใส่รหัส แล้วกด "เพิ่มผู้ทดสอบใหม่" หนึ่งคนต่อผู้ทดสอบหนึ่งคน หรือใช้ LINE จริงหากเชื่อม OA แล้ว |
| เจ้าหน้าที่ | เข้าสู่ระบบด้วยบัญชี Agent หรือ Supervisor ตามรายชื่อใน `web/scripts/seed.ts` |
| ผู้ดูแลระบบ | บัญชี Admin ใช้กับงาน D1 (Bot Flow Builder) · เข้าสู่ระบบครั้งแรกต้องตั้งค่า MFA ด้วยแอป authenticator (ADR 0006) เตรียมโทรศัพท์ไว้ |
| ผู้สังเกต | บันทึกเวลาที่ใช้ จุดที่ลังเล และคำพูดของผู้ทดสอบลงแบบฟอร์มท้ายเอกสาร |

ก่อนรอบทดสอบจริงควรรัน `SEED_SAMPLES=false pnpm db:reset` เพื่อเริ่มจากระบบที่ไม่มีเคส หรือคงข้อมูลตัวอย่างไว้หากต้องการให้แดชบอร์ดมีตัวเลข

## งานสำหรับผู้แจ้ง (ประมาณ 15 นาที)

อ่านโจทย์ให้ผู้ทดสอบฟังโดยไม่อธิบายวิธีใช้ แล้วสังเกตว่าผู้ทดสอบทำได้เองหรือไม่

| # | โจทย์ | สิ่งที่สังเกต | เกณฑ์ผ่าน |
| --- | --- | --- | --- |
| R1 | "คุณเพิ่งเพิ่มเพื่อน LINE ศูนย์แจ้งปัญหา กรุณาลงทะเบียนให้เรียบร้อย" | อ่านประกาศความเป็นส่วนตัวหรือไม่ · เข้าใจช่องรหัสลูกค้าหรือไม่ | ลงทะเบียนสำเร็จภายใน 2 นาที |
| R2 | "เข้าระบบ ERP ไม่ได้ตั้งแต่เช้า ทีมทำงานไม่ได้ กรุณาแจ้งเคส" | เลือกหมวดถูกหรือไม่ · ตอบคำถามวันที่/เวลาได้หรือไม่ | ได้เลขเคสภายใน 3 นาที · priority เป็น P2 |
| R3 | "แนบภาพหน้าจอ error ด้วย แล้วแก้คำตอบข้อผลกระทบก่อนยืนยัน" | หาปุ่ม "เสร็จ" เจอหรือไม่ · ใช้ "แก้ไขข้อ" ได้หรือไม่ | เคสมีรูปแนบและคำตอบที่แก้แล้ว |
| R4 | "ดูว่าเคสของคุณอยู่สถานะใด" | ใช้เมนู "เคสของฉัน" หรือพิมพ์เลขเคส | เห็นสถานะและผู้รับผิดชอบ |
| R5 | (หลังเจ้าหน้าที่ขอข้อมูลเพิ่ม) "ตอบเจ้าหน้าที่ในแชท" | พิมพ์ตอบในแชทได้ทันทีหรือไม่ | ข้อความเข้าเคสและสถานะเปลี่ยนเป็น "กำลังดำเนินการ" |
| R6 | (หลังเจ้าหน้าที่แจ้งว่าแก้แล้ว) "ยืนยันผลและให้คะแนน" | เข้าใจปุ่ม "ยังไม่เรียบร้อย" หรือไม่ | เคสปิดพร้อมคะแนน หรือเปิดใหม่หากเลือกยังไม่เรียบร้อย |
| R7 | "ระหว่างแจ้งเคส ลองพิมพ์ ย้อนกลับ แล้วพิมพ์ ยกเลิก" | คำสั่งทำงานตามที่คาดหรือไม่ | bot ตอบถูกต้องทุกคำสั่ง |

## คำถามหลังทดสอบ

1. ขั้นตอนใดใช้เวลานานหรือทำให้ลังเลมากที่สุด
2. ก่อนตอบคำถามข้อแรก หากระบบแสดงวิธีแก้ปัญหาเบื้องต้น 1–3 ข้อ ผู้แจ้งจะลองทำตามก่อนหรือไม่ (วัดความต้องการ FAQ ตาม D-012)
3. ข้อความของ bot มีตรงไหนที่ไม่ชัดเจนหรือไม่สุภาพ
4. ต้องการข้อมูลใดในหน้ารายละเอียดเคสที่ยังไม่มี
5. ให้คะแนนความง่ายในการใช้งาน 1–5 แยกฝั่ง LINE และฝั่งเว็บ
